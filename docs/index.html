Onchain Attribution Kit

Capture UTMs at wallet connect, join campaigns to Dune activity, and alert to Telegram, Discord or Slack. Know which campaigns produce wallets that transact, not just connect.

What an alert looks like

Onchain attribution alert

Campaign: launch-q2-2026
Source: x / social
Wallets captured: 42
Converted wallets: 9
Conversion rate: 21.4%
Top action: first_swap
Window: last 24h
GA4 sees the click. Dune sees the transaction. Nothing connects them.

The problem

Web3 protocols spend on influencers, paid social and KOL campaigns and have no way to know which of those wallets ever did a swap, staked or bridged. This kit fills that gap with a lightweight, forkable attribution layer you own entirely.

Built for Web3 growth leads, protocol engineers who want commented templates for attribution plumbing, and agencies or consultants who need a repeatable attribution baseline.

How it works

From campaign link to onchain conversion

The browser snippet keeps campaign context until a wallet connects, the receiver stores one event per connect, and the Dune query pack joins those wallets to what they did onchain.

What's included

Four parts, each one forkable

Every part lives in plain files you can read and change. The architecture is designed for adapters: new chains and new alert channels plug in.

Capture snippet

src/capture/browser-snippet.ts

  • Reads UTM params and crypto-native params (ref, kol, invite, campaign_id)
  • Persists campaign context in localStorage for a configurable window (default 7 days)
  • On wallet connect, POSTs an attribution payload to your backend
  • No email, IP or device fingerprint. Opt out with window.ONCHAIN_ATTRIBUTION_DISABLED = true

Event receiver

src/server/api.ts

  • POST /api/attribution/event validates and stores events
  • GET /api/health health check
  • GET /api/events.csv CSV export for Dune (dev only)
  • Auth via the ONCHAIN_ATTRIBUTION_WRITE_KEY header
  • Default storage: append-only JSONL + CSV in data/

Alert channels

src/alerts/

  • Telegram: plain text
  • Discord: Markdown
  • Slack: Block Kit
  • Dry-run test: npm run test:alert

Claude Code agent

src/agents/claude-code-agent.md

  • Inspect event files and summarize activity
  • Compare campaigns across time windows
  • Detect anomalies (drop-off, wallet quality shift)
  • Draft daily summaries and recommend scale, pause or inspect

Quickstart

Running locally in five steps

Click "Connect Wallet" on the test page to fire an attribution event, then check that it was stored.

bash

# 1. Clone the repo
git clone https://github.com/gmangabeira/onchain-attribution-kit.git
cd onchain-attribution-kit

# 2. Install dependencies
npm install

# 3. Configure env vars
cp .env.example .env
# Edit .env: set ONCHAIN_ATTRIBUTION_WRITE_KEY and optionally alert vars

# 4. Start the local server
npm run dev

# 5. Open the test page with UTM params to simulate an attribution event
# http://localhost:3000/?utm_source=x&utm_medium=social&utm_campaign=launch-q2-2026&utm_content=thread-01

Verify the event

cat data/events.jsonl

Test alert formatting (dry run, no messages sent)

npm run test:alert

Send to one channel

ts-node scripts/send-test-alert.ts --channel telegram

Environment variables

Only ONCHAIN_ATTRIBUTION_WRITE_KEY is required. Optional: PORT (default 3000), EVENTS_FILE, ATTRIBUTION_WINDOW_DAYS (default 7), ALERT_CHANNELS, and the Telegram, Discord or Slack credentials for the channels you use.

Dune SQL query pack

Five commented, parameterized queries

In sql/dune/. Drop your campaign slug and chain ID into the variables block at the top and run against your uploaded events.csv.

FilePurpose
01_campaign_wallets.sqlBase table of attributed wallets from CSV upload
02_first_onchain_action.sqlFirst onchain action after wallet connect (EVM example)
03_campaign_conversion_summary.sqlCampaign-level metrics: wallets, conversions, rate, volume
04_channel_quality_score.sqlLightweight wallet quality scoring
05_daily_attribution_timeseries.sqlDaily time series for dashboard charts

See the example attribution dashboard for the kind of view these queries feed.

Before production

Auth

The write key is a shared secret. Move to per-campaign keys or signed JWTs for higher-volume use.

Storage

Replace LocalFileAdapter with a Postgres or Supabase adapter for durability and query access.

CORS

Restrict Access-Control-Allow-Origin to your frontend domain.

HTTPS

Run behind a reverse proxy (nginx, Cloudflare) with TLS.

Rate limiting

Add rate limiting middleware to the event endpoint.

Limitations

A starting point, not a full attribution system

It does not solve:

  • Multi-wallet identity resolution
  • Multi-touch deterministic attribution
  • Bot and sybil detection
  • Privacy compliance advice
  • Hosted analytics or a SaaS dashboard

Wallet quality scoring is a heuristic, not a guarantee. Full list in docs/limitations.md.

I built this because every Web3 growth team I audited was flying blind on which campaigns actually produced onchain activity. Attribution is one pillar of the Web3 growth audit methodology I use with protocols.
